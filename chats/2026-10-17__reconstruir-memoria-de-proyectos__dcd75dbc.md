### 2. HERRAMIENTA TÉCNICA: SCRIPT DE AUDITORÍA MASIVA (PYTHON)

Para "recuperar" lo que hay en tu cuenta y limpiar la RAM mental de los 487 repositorios, he diseñado este script en Python. Utiliza la **API de GitHub** para extraer la metadata real de todos tus repositorios, identificar cuáles están vacíos, cuáles son forks, cuáles no tienen actividad desde 2025 y agruparlos para que puedas tomar decisiones de fusión o archivo masivo.

**Requisitos:**
1. Un **Personal Access Token (PAT)** de GitHub con permisos de lectura (`repo:status`).
2. Python instalado y las librerías `requests` y `pandas` (`pip install requests pandas`).

```python
import requests
import pandas as pd
import time
from datetime import datetime

# --- CONFIGURACIÓN ---
GITHUB_TOKEN = "tu_token_aqui"  # Reemplaza con tu PAT
USERNAME = "tu_usuario_aqui"    # Reemplaza con tu usuario de GitHub
OUTPUT_CSV = "auditoria_487_repos.csv"

headers = {
    "Authorization": f"token {GITHUB_TOKEN}",
    "Accept": "application/vnd.github.v3+json"
}

def fetch_all_repos():
    url = f"https://api.github.com/users/{USERNAME}/repos?per_page=100&type=owner"
    all_repos = []
    
    print("Iniciando extracción de metadata de GitHub...")
    while url:
        response = requests.get(url, headers=headers)
        if response.status_code != 200:
            print(f"Error en la API: {response.status_code}")
            break
        
        all_repos.extend(response.json())
        
        # Paginación automática
        url = response.links.get('next', {}).get('url')
        time.sleep(0.5) # Respetar rate limits
        
    print(f"Total de repositorios extraídos: {len(all_repos)}")
    return all_repos

def analyze_repos(repos):
    data = []
    current_year = datetime.now().year
    
    for repo in repos:
        # Detección de repositorios huérfanos o de prueba
        pushed_year = int(repo['pushed_at'][:4]) if repo['pushed_at'] else 0
        is_abandoned = (current_year - pushed_year) > 1
        
        data.append({
            "Nombre": repo['name'],
            "Producto_Familia": "Sin Clasificar", # Rellenar manualmente en Excel
            "Es_Fork": repo['fork'],
            "Archivado": repo['archived'],
            "Tamaño_KB": repo['size'],
            "Lenguaje_Principal": repo['language'] or 'N/A',
            "Ultimo_Push": repo['pushed_at'],
            "Abandonado": is_abandoned,
            "URL": repo['html_url']
        })
        
    df = pd.DataFrame(data)
    
    # Ordenar por abandono y tamaño para facilitar la limpieza
    df = df.sort_values(by=['Abandonado', 'Tamaño_KB'], ascending=[False, False])
    df.to_csv(OUTPUT_CSV, index=False, encoding='utf-8')
    print(f"Auditoría completada. Archivo generado: {OUTPUT_CSV}")
    
    # Resumen rápido en consola
    print("\n--- RESUMEN DE EJECUCIÓN ---")
    print(f"Repositorios Abandonados (+1 año): {df['Abandonado'].sum()}")
    print(f"Forks Huérfanos: {df[df['Es_Fork'] == True].shape[0]}")
    print(f"Repositorios Vacíos (0 KB): {df[df['Tamaño_KB'] == 0].shape[0]}")

if __name__ == "__main__":
    repos = fetch_all_repos()
    if repos:
        analyze_repos(repos)
```

### 4. BARRERA TÉCNICA: RESTRICCIÓN DE PERMISOS (FINE-GRAINED TOKENS)

La indicación más importante que puedo darte es que **las instrucciones de texto no detienen a los agentes de código autónomos**. Si usas herramientas como Cursor, Devin, o GitHub Actions con permisos de escritura, debes cortar el problema de raíz a nivel de autenticación.

Los Tokens de Acceso Personal (PAT) clásicos de GitHub tienen un permiso llamado `repo` (Full control of private repositories) que incluye la capacidad de crear repositorios. **Debes revocar ese token inmediatamente.**

**Pasos para blindar tu cuenta:**
1. Ve a GitHub > Settings > Developer Settings > **Fine-grained personal access tokens**.
2. Genera un nuevo token para tus IAs y Agentes.
3. En **Repository permissions**, configura lo siguiente:
   - `Contents`: **Read and write** (Para que pueda editar código).
   - `Pull requests`: **Read and write** (Para que pueda gestionar merges).
   - `Administration`: **Read-only** o **No access** (Esto bloquea matemáticamente la creación, borrado o transferencia de repositorios).
   - `Metadata`: **Read-only**.
4. Usa este nuevo token en tus aplicaciones de IA.

Si la IA intenta ejecutar `gh repo create` o una llamada POST a la API, GitHub devolverá un error `403 Forbidden`. La IA recibirá el error, entenderá que no tiene permisos de administración y se verá forzada a sugerirte que crees el repositorio manualmente o, mejor aún, a adaptar el código a un repositorio existente.

```bash
#!/usr/bin/env bash
set -uo pipefail

OWNER="${1:?Uso: ./forense-github.sh TU_USUARIO_GITHUB}"
WORKDIR="rescate-$(date +%Y%m%d-%H%M)"

mkdir -p "$WORKDIR"/{mirrors,reportes,bundles,logs}

export GIT_TERMINAL_PROMPT=0

echo "Creando inventario de repositorios..."

gh repo list "$OWNER" --limit 1000 \
  --json name,description,isArchived,isFork,diskUsage,pushedAt,updatedAt,primaryLanguage,defaultBranchRef \
  --jq 'map({
    name,
    isArchived,
    isFork,
    diskUsage,
    pushedAt,
    updatedAt,
    language: (.primaryLanguage.name? // ""),
    defaultBranch: (.defaultBranchRef.name? // "")
  })' > "$WORKDIR/repos_inventory.json"

jq -r '.[].name' "$WORKDIR/repos_inventory.json" > "$WORKDIR/repo_names.txt"

echo "Inventario guardado en $WORKDIR/repos_inventory.json"
echo "Comenzando extracción profunda..."

while IFS= read -r repo; do
  [ -z "$repo" ] && continue

  echo "=========================================="
  echo "Procesando: $repo"

  MIRROR_DIR="$WORKDIR/mirrors/$repo.git"
  REPORT_DIR="$WORKDIR/reportes/$repo"

  mkdir -p "$REPORT_DIR"

  # Clone espejo, primero parcial si es posible
  if ! git clone --quiet --mirror --filter=blob:none \
      "https://github.com/$OWNER/$repo.git" "$MIRROR_DIR" 2>"$REPORT_DIR/clone_error.log"; then

    echo "Clonación parcial falló, intentando clonación espejo completa..."

    rm -rf "$MIRROR_DIR"

    if ! git clone --quiet --mirror \
        "https://github.com/$OWNER/$repo.git" "$MIRROR_DIR" 2>>"$REPORT_DIR/clone_error.log"; then
      echo "$repo" >> "$WORKDIR/logs/failed_repos.txt"
      echo "ERROR: no se pudo clonar $repo"
      continue
    fi
  fi

  # Backup completo en bundle
  git -C "$MIRROR_DIR" bundle create "$WORKDIR/bundles/$repo.bundle" --all \
    >/dev/null 2>&1 || true

  # Ramas
  git -C "$MIRROR_DIR" for-each-ref refs/heads \
    --format='branch|%(refname:short)|%(objectname)|%(committerdate:iso8601)|%(authorname)|%(subject)' \
    > "$REPORT_DIR/branches.txt" 2>/dev/null || true

  # Tags
  git -C "$MIRROR_DIR" for-each-ref refs/tags \
    --format='tag|%(refname:short)|%(objectname)|%(committerdate:iso8601)|%(authorname)|%(subject)' \
    > "$REPORT_DIR/tags.txt" 2>/dev/null || true

  # Commits con métricas de archivos cambiados
  git -C "$MIRROR_DIR" log --all --date=iso --numstat \
    --pretty=format:'COMMIT|%H|%P|%an|%ae|%ad|%s' \
    > "$REPORT_DIR/commits_numstat.txt" 2>/dev/null || true

  # Archivos en HEAD, si existe
  git -C "$MIRROR_DIR" ls-tree -r --name-only HEAD \
    > "$REPORT_DIR/files_head.txt" 2>/dev/null || true

  # Resumen por repo
  commit_count=$(git -C "$MIRROR_DIR" rev-list --all --count 2>/dev/null || echo 0)
  branch_count=$(git -C "$MIRROR_DIR" for-each-ref refs/heads --format='%(refname)' | wc -l | tr -d ' ')
  tag_count=$(git -C "$MIRROR_DIR" for-each-ref refs/tags --format='%(refname)' | wc -l | tr -d ' ')
  latest_commit=$(git -C "$MIRROR_DIR" log -1 --date=iso --format=%ad 2>/dev/null || echo "")

  printf 'repo,commits_all,branches,tags,latest_commit_date\n' > "$REPORT_DIR/summary.csv"
  printf '%s,%s,%s,%s,%s\n' "$repo" "$commit_count" "$branch_count" "$tag_count" "$latest_commit" \
    >> "$REPORT_DIR/summary.csv"

done < "$WORKDIR/repo_names.txt"

echo ""
echo "Extracción terminada."
echo "Resultados en: $WORKDIR"
echo ""
echo "Archivos importantes:"
echo "  $WORKDIR/repos_inventory.json"
echo "  $WORKDIR/reportes/"
echo "  $WORKDIR/bundles/"
```

## 4. Qué extrae esta herramienta

Por cada repositorio extrae:

### Ramas

Archivo:

Archivo:

```text
tags.txt
```

### Commits con cambios

Archivo:

```text
commits_numstat.txt
```

Contiene commits y archivos modificados:

```text
COMMIT|abc123|parent...|Autor|correo|2026-09-12 10:11:22 +0000|Agregar login
```

Donde:


```csv
repo,commits_all,branches,tags,latest_commit_date
```

## 5. Convertir todo en reportes CSV/Excel

La extracción genera muchos archivos por repo. Ahora conviene unirlos en tablas.

Crea un archivo:

```bash
consolidar_reportes.py
```

Pega esto:

```python
from pathlib import Path
import pandas as pd
import sys

BASE = Path(sys.argv[1]) if len(sys.argv) > 1 else sorted(Path('.').glob('rescate-*'))[-1]

repo_rows = []
branch_rows = []
commit_metrics_rows = []

# Inventario general
inventory_path = BASE / "repos_inventory.json"
inventory_df = None
if inventory_path.exists():
    inventory_df = pd.read_json(inventory_path)

# Resúmenes por repo
for summary_file in (BASE / "reportes").glob("*/summary.csv"):
    try:
        df = pd.read_csv(summary_file)
        repo_rows.append(df)
    except Exception as e:
        print(f"Error leyendo {summary_file}: {e}")

# Ramas
for branch_file in (BASE / "reportes").glob("*/branches.txt"):
    repo = branch_file.parent.name
    try:
        text = branch_file.read_text(errors="ignore")
        for line in text.splitlines():
            line = line.strip()
            if not line:
                continue
            parts = line.split("|", 5)
            if len(parts) == 6:
                branch_rows.append({
                    "repo": repo,
                    "type": parts[0],
                    "branch": parts[1],
                    "sha": parts[2],
                    "date": parts[3],
                    "author": parts[4],
                    "subject": parts[5]
                })
    except Exception as e:
        print(f"Error leyendo {branch_file}: {e}")

# Métricas de commits
for commit_file in (BASE / "reportes").glob("*/commits_numstat.txt"):
    repo = commit_file.parent.name
    commits = 0
    additions = 0
    deletions = 0
    file_events = 0
    authors = set()
    last_date = ""

    try:
        text = commit_file.read_text(errors="ignore")

        for line in text.splitlines():
            if line.startswith("COMMIT|"):
                commits += 1
                parts = line.split("|")
                if len(parts) >= 7:
                    author = parts[3]
                    date = parts[5]
                    if author:
                        authors.add(author)
                    if date:
                        last_date = date
            else:
                parts = line.split("\t")
                if len(parts) == 3:
                    add, delete, filename = parts

                    if add.isdigit():
                        additions += int(add)
                    if delete.isdigit():
                        deletions += int(delete)

                    file_events += 1

        commit_metrics_rows.append({
            "repo": repo,
            "commits": commits,
            "file_change_events": file_events,
            "additions": additions,
            "deletions": deletions,
            "authors_count": len(authors),
            "last_commit_date": last_date
        })

    except Exception as e:
        print(f"Error leyendo {commit_file}: {e}")

# Convertir a DataFrames
summary_df = pd.concat(repo_rows, ignore_index=True) if repo_rows else pd.DataFrame()
branches_df = pd.DataFrame(branch_rows)
commit_metrics_df = pd.DataFrame(commit_metrics_rows)

# Clasificación por familia/proyecto
def family_from_name(name: str) -> str:
    n = str(name).lower()

    if "judas" in n:
        return "JUDAS"
    if "belentani" in n:
        return "BELENTANI"
    if "noi" in n or "noia" in n:
        return "NOIACORE"
    if "lingua" in n:
        return "LINGUAFORGE"
    if "mano" in n or "manos" in n:
        return "MANOSABIERTAS"
    if "duck" in n:
        return "DUCK"
    if "open" in n and "school" in n:
        return "OPENSCHOOL"

    return "SIN_CLASIFICAR"

if not summary_df.empty:
    summary_df["family"] = summary_df["repo"].apply(family_from_name)

if not branches_df.empty:
    branches_df["family"] = branches_df["repo"].apply(family_from_name)

if not commit_metrics_df.empty:
    commit_metrics_df["family"] = commit_metrics_df["repo"].apply(family_from_name)

# Unir con inventario si existe
if inventory_df is not None and not summary_df.empty:
    summary_df = summary_df.merge(
        inventory_df,
        left_on="repo",
        right_on="name",
        how="left"
    )

# Guardar reportes
summary_out = BASE / "REPO_SUMMARY.csv"
branches_out = BASE / "BRANCHES_ALL.csv"
commits_out = BASE / "COMMIT_METRICS.csv"

summary_df.to_csv(summary_out, index=False, encoding="utf-8")
branches_df.to_csv(branches_out, index=False, encoding="utf-8")
commit_metrics_df.to_csv(commits_out, index=False, encoding="utf-8")

print("Reportes generados:")
print(summary_out)
print(branches_out)
print(commits_out)
```

## 6. Cómo interpretar los reportes para recuperar el daño

### `REPO_SUMMARY.csv`

Te dice qué repos tienen vida real.

Columnas importantes:

```csv
repo
commits_all
branches
tags
latest_commit_date
family
isArchived
isFork
diskUsage
pushedAt
updatedAt
language
defaultBranch
```

Reglas prácticas:

| Señal | Interpretación |
|---|---|
| `commits_all = 0` | Repo vacío o casi inútil |
| `commits_all > 20` | Probablemente tiene trabajo real |
| `latest_commit_date` reciente | Puede seguir activo |
| `isFork = true` | Probablemente no es proyecto propio, salvo que tenga cambios |
| `diskUsage` muy pequeño | Puede ser prototipo o residuo |
| Varias ramas sin commits recientes | Posible experimento abandonado |
| Mismo `family` en varios repos | Candidatos a fusionar |

---

### `BRANCHES_ALL.csv`

Te dice qué ramas existen.

Ejemplo:

```csv
repo,type,branch,sha,date,author,subject,family
judas-web,branch,main,abc123,2026-09-10,Autor,Último cambio,JUDAS
judas-web,branch,feature/login,def456,2026-07-01,Autor,Login experimental,JUDAS
```

Esto sirve para detectar:

- Ramas duplicadas.
- Ramas antiguas.
- Ramas con funcionalidades perdidas.
- Ramas que deberían convertirse en carpetas o módulos dentro de un repo principal.

---

### `COMMIT_METRICS.csv`

Te dice qué repos tienen movimiento real.

Columnas:

```csv
repo
commits
file_change_events
additions
deletions
authors_count
last_commit_date
family
```

Reglas:

| Señal | Interpretación |
|---|---|
| `additions` altas | Hubo desarrollo real |
| `commits > 50` | Proyecto con historial |
| `file_change_events` alto | Muchos archivos tocados |
| `authors_count = 1` | Probablemente trabajo personal |
| `commits = 1` | Posible repo creado automáticamente |
| `last_commit_date` muy antiguo | Candidato a archivar |

## 8. Recuperar el daño de verdad: consolidar proyectos

El objetivo final no es tener 500 repos, sino tener pocos productos bien organizados.

Por ejemplo:

```text
JUDAS/
BELENTANI/
NOIACORE/
LINGUAFORGE/
MANOSABIERTAS/
OPENSCHOOL/
DUCK/
```

Puedes hacer tres movimientos:

---

### Opción A — Absorber repos sin historia, solo código actual

Si solo quieres rescatar el código actual:

```bash
mkdir -p rescate-final
cd rescate-final

git clone https://github.com/TU_USUARIO/REPO_DESTINO.git
cd REPO_DESTINO

mkdir -p legacy/REPO_ANTIGUO

git clone --depth 1 https://github.com/TU_USUARIO/REPO_ANTIGUO.git tmp_repo

cp -r tmp_repo/* legacy/REPO_ANTIGUO/

git add legacy/REPO_ANTIGUO
git commit -m "Rescate: importar código de REPO_ANTIGUO como subcarpeta"
git push
```

Esto es rápido, pero pierde historia Git.

---

### Opción B — Absorber con historia usando `git subtree`

Si quieres traer historia de forma simple:

```bash
cd REPO_DESTINO

git subtree add \
  --prefix=legacy/REPO_ANTIGUO \
  https://github.com/TU_USUARIO/REPO_ANTIGUO.git \
  main
```

Si quieres historia resumida:

```bash
git subtree add \
  --prefix=legacy/REPO_ANTIGUO \
  https://github.com/TU_USUARIO/REPO_ANTIGUO.git \
  main \
  --squash
```

`--squash` conserva menos historia pero es más simple.

---

### Opción C — Absorber con historia completa usando `git filter-repo`

Esta es la mejor opción para mover un repo entero dentro de otro sin perder historia.

Instala `git-filter-repo`:

```bash
pip install git-filter-repo
```

Clona el repo antiguo:

```bash
git clone https://github.com/TU_USUARIO/REPO_ANTIGUO.git
cd REPO_ANTIGUO
```

Muévelo a una subcarpeta:

```bash
git filter-repo --to-subdirectory-filter legacy/REPO_ANTIGUO
```

Ahora ve al repo destino:

```bash
cd ..
git clone https://github.com/TU_USUARIO/REPO_DESTINO.git
cd REPO_DESTINO
```

Agrega el repo antiguo como remoto local:

```bash
git remote add old_repo ../REPO_ANTIGUO
git fetch old_repo
```

Fusiona:

```bash
git merge --allow-unrelated-histories old_repo/main
```

Si la rama principal no es `main`, usa la correcta:

```bash
git merge --allow-unrelated-histories old_repo/master
```

Limpia el remoto temporal:

```bash
git remote remove old_repo
git push
```

Esto preserva commits, ramas fusionadas y autores.

## 9. Qué hacer con los repos ya analizados

Después de revisar los CSV, clasifica cada repo en uno de estos estados:

### `KEEP`

Proyecto real, activo o importante.

Se conserva como repo principal o módulo central.

Ejemplo:

```text
judas-web → KEEP dentro de familia JUDAS
noiacore-engine → KEEP dentro de familia NOIACORE
```

---

### `MERGE`

Repo útil pero duplicado o demasiado pequeño.

Se absorbe dentro del repo principal de su familia.

Ejemplo:

```text
judas-login-test → MERGE dentro de judas-web como legacy/judas-login-test
belentani-gallery-v2 → MERGE dentro de belentani-omega como legacy/gallery-v2
```

---

### `ARCHIVE`

Repo viejo, sin actividad, pero con posible valor histórico.

En GitHub:

1. Ir al repo.
2. Settings.
3. Marcar como archived.

No borra nada, pero evita confusión.

---

### `DISCARD`

Repo vacío, fork sin cambios, prueba inútil o duplicado exacto.

Solo descartar después de tener bundle y reporte.

2. Si existe un fork, el fork puede conservar código.

## 14. Sobre “MNPN”

No tengo “MNPN” como comando, métrica o herramienta estándar de Git/GitHub. Puede ser:

- Un error de dictado.
- Una métrica interna tuya.
- Una abreviación de algo que quieres medir.
- Algo parecido a “métricas por commits”.

Si me dices qué significa exactamente MNPN, puedo adaptar el extractor para calcular eso específicamente.

Mientras tanto, el pipeline de arriba ya extrae métricas útiles:

```text
- cantidad de commits
- cantidad de ramas
```
