# 1. Concepto central

**AZUL FORGE** es una aplicación web full stack que funciona como un estudio de generación de proyectos dentro del navegador.

El usuario entra desde Chrome, escribe una idea, elige un estilo visual, selecciona una plantilla y la aplicación genera un proyecto completo con:

- Código profesional.
- Estética artística.
- Estructura lista para producción.
- Documentación.
- Tests básicos.
- Configuración de CI/CD.
- Archivo ZIP descargable.
- Instrucciones para subirlo a GitHub.

No necesita pagos, suscripciones ni APIs externas obligatorias.

La herramienta puede usar generación determinista basada en reglas, plantillas inteligentes y composición automática de código. Si el entorno online donde la generas tiene IA integrada, puede aprovecharla. Si no, también funciona sin depender de servicios de pago.

---

# 2. Por qué este proyecto tiene alta relevancia

Este proyecto encaja con varias tendencias importantes del desarrollo web actual:

## 2.1. Herramientas de generación de aplicaciones

Hay mucho interés en herramientas que convierten prompts o configuraciones en aplicaciones. Pero muchas generan código genérico o frágil.

**AZUL FORGE** se diferencia porque no solo genera código, sino que también genera:

- Identidad visual.
- Documentación.
- Tests.

- Preparación para GitHub.

**AZUL FORGE** une ambas cosas:

# 9. Stack técnico recomendado para AZUL FORGE

Este stack está pensado para verse profesional, ser generable por herramientas online y mantener buena calidad.

## 9.1. Frontend

- **Next.js App Router**
- **TypeScript estricto**
- **React**
- **Tailwind CSS**
- **shadcn/ui**
- **Radix UI**
- **Framer Motion**
- **Lucide Icons**
- **CodeMirror 6** para ver código generado

## 9.2. Backend

- **Next.js Route Handlers**
- API interna en `/api`
- Validación con **Zod**
- Lógica de generación server-side o client-side

## 9.3. Base de datos

Opción simple y profesional:

- **SQLite**
- **Prisma ORM** o **Drizzle ORM**

Para MVP también se puede usar:

- Plantillas en JSON.
- Estado en memoria.
- `localStorage` para borradores.

Pero si quieres que sea verdaderamente full stack, usa SQLite para guardar:

- Plantillas.
- Historial de generación.
- Informes de calidad.
- Configuraciones favoritas.

## 9.4. Exportación

- **JSZip**
- **file-saver**

Alternativa server-side:

- **archiver**

Para MVP, JSZip en cliente es más simple.

## 9.5. Calidad de código

- **ESLint**
- **Prettier**
- **Stylelint**
- **TypeScript strict**
- **Vitest**
- **React Testing Library**
- **Playwright**

## 9.6. CI/CD

- **GitHub Actions**

Archivo:

```yaml
.github/workflows/ci.yml
```

Debe ejecutar:

```bash
npm install

npm run build
```

Para que el proyecto sea profesional:
